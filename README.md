# InSales MCP

Подключите магазин InSales к Codex, Cursor или другому MCP-клиенту, чтобы читать и менять данные магазина из чата. Вы описываете задачу обычными словами, а помощник обращается к InSales через API с правами вашего ключа.

- **Товары и каталог.** Посмотреть список товаров, проверить варианты и изображения, обновить карточку или состав категории.
- **Контент и навигация.** Прочитать и отредактировать страницы, статьи и меню.
- **Темы и виджеты.** Узнать, какие виджеты стоят на странице, прочитать их настройки и исходники, изменить виджет или блок. Запись через API редактора тем поддерживается для тем поколения 4.

Например, попросите «Покажи первые пять товаров с ID и названиями» или «Найди виджет с рекомендациями на главной странице и покажи его настройки». Для изменений указывайте, какой товар, страницу или тему нужно править. Правки в опубликованной теме сразу отражаются на витрине. Если хотите разрешить запись только в определённую тему, задайте `INSALES_MCP_THEME_ID`. Правки общих блоков, панелей и шаблонов могут затронуть несколько тем даже при включённом ограничении. Чтобы оставить запись только для тем, виджетов и файлов, а товары, каталог и страницы читать без изменений, задайте `INSALES_MCP_ACCESS=theme_files`.

## Подключение магазина

1. Подготовьте публичный HTTPS-адрес магазина, идентификатор и пароль API-ключа InSales. Нужны Node.js 22.13 или выше и npm.
2. В папке проекта выполните `npm ci --include=dev`. Команда установит зависимости для сборки и автоматически соберёт сервер.
3. Добавьте сервер в настройки MCP-клиента. Клиент запускает `node <repo>/bin/insales-mcp.mjs` и общается с процессом через `stdio`. Для JSON-конфигурации используйте [mcp.example.json](mcp.example.json).
4. Перезапустите клиент и попросите помощника «Покажи первую страницу товаров из моего магазина InSales». Список товаров или пустая страница подтверждают, что чтение каталога работает.

Каждому процессу соответствует один магазин. Для нескольких магазинов добавьте отдельную запись MCP с собственным именем и ключом для каждого магазина. Без ключа доступны встроенные справочники по темам и виджетам.

### Настройка Codex

```toml
[mcp_servers.insales]
command = "node"
args = ["<repo>/bin/insales-mcp.mjs"]

[mcp_servers.insales.env]
INSALES_STORE_URL = "https://shop.myinsales.ru"
INSALES_STORE_NAME = "Example shop"
INSALES_API_KEY_ID = "<api-key-id>"
INSALES_API_KEY_PASSWORD = "<api-key-password>"
```

Замените `<repo>` абсолютным путём к проекту и подставьте данные магазина. API-ключ хранится в этом файле открытым текстом. Ограничьте доступ к файлу на уровне ОС.

Чтобы передавать реквизиты через окружение, задайте переменные перед запуском Codex и добавьте `env_vars` в секцию `[mcp_servers.insales]` вместо таблицы `[mcp_servers.insales.env]`.

```toml
env_vars = [
  "INSALES_STORE_URL",
  "INSALES_STORE_NAME",
  "INSALES_API_KEY_ID",
  "INSALES_API_KEY_PASSWORD",
]
```

## Режимы и доступ к темам

Настройки применяются при запуске сервера. После изменения перезапустите MCP-клиент.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `INSALES_MCP_MODE` | `code` | В режиме `code` помощник может собрать несколько действий в один вызов. Выберите `tools`, если нужны именованные инструменты. |
| `INSALES_MCP_FULL_API` | `false` | Значение `true` подключает каталог опубликованных операций REST API InSales. |
| `INSALES_MCP_ACCESS` | `full` | `theme_files` разрешает запись только в темы, виджеты, блоки и раздел «Файлы» (`/admin/theme_editor/v1`, `/admin/themes`, `/admin/files`). Товары, каталог, страницы, меню и остальные данные можно читать. Ограничение действует и на методы полного REST API. Вместе с `INSALES_MCP_THEME_ID` действуют оба правила. |
| `INSALES_MCP_THEME_ID` | Пусто | Положительный ID разрешает запись в эту тему и сохраняет чтение всех тем. Публикация и дублирование тем блокируются. Доступ к общим ресурсам и данным магазина по-прежнему определяют права API-ключа. |

В режиме `tools` начните с `list_stores`, затем вызовите `read_content` с `store_id`, `kind: "product"` и `mode: "list"`. Для операций с темой `theme_api` показывает схемы. Передайте имя операции и её `arguments` в `theme_read` или `theme_write`. При включённом REST-каталоге эту же роль выполняют `api_catalog`, `api_read` и `api_write`. [Справочник REST API InSales](https://api.insales.ru/)

В режиме `code` этот пример можно передать как `code` в `execute_read`.

```js
const [store] = await insales.list_stores({});
return await insales.read_content({
  store_id: store.id,
  kind: "product",
  mode: "list",
  per_page: 10,
});
```

Для поиска методов используйте `catalog.search({domain: "themes"})` или поиск по `query`. Вызов `catalog.describe({names: ["get_widget"]})` возвращает схему аргументов. Дополнительные REST-методы находятся в области `public_api`. Скрипт выполняется в песочнице с доступом к методам InSales, каталогу и журналу. На один запуск выделяется 5 секунд выполнения JavaScript, 60 секунд общего времени и до 100 вызовов. После таймаута сервер ждёт начатые вызовы ещё до 2 секунд. Если они завершатся позже, их результаты можно проверить в журнале запуска записи.

## Правки и проверка результата

Для правок темы начните с `list_themes` и `get_page_structure`. Перед изменением прочитайте ресурс. В PATCH и PUT передавайте исходный `updated_at` как `expected_updated_at`. Для обновления товаров, меню и контента передавайте `base_revision`, если этого требует операция. При конфликте заново прочитайте ресурс и сверьте правку с текущими данными.

Настройки экземпляра виджета меняет `update_widget`, блоки — `update_widget_block` и `replace_widget_blocks`, код типа — `update_widget_type`. Для независимой правки системного или общего типа сначала используйте `make_widget_custom`. Для отдельного шаблона страницы используйте `create_unique_template` с `assign: true`. Уже существующий шаблон назначает `assign_page_template`. Результат можно проверить через `get_page_widgets`, `render_widget` и на витрине. [Контракт редактора тем](knowledge/themes-api.md)

Встроенные `search_knowledge` и `get_knowledge_section` открывают справочники. `get_widget_standards` подбирает правила разработки по сценарию и паттернам, а `detail: "full"` добавляет общие правила. [Руководство по запасным изображениям для блоков](knowledge/widget-development/fallback-images.md)

### Если результат записи неизвестен

- В режиме `tools` заранее передайте UUID как `operation_id`, если метод его принимает. При обрыве проверьте журнал через `get_operation` и прочитайте текущее состояние изменяемых данных. Для дублирования темы `retry_theme_operation` может повторить запрос с прежним ключом идемпотентности в пределах часа.
- В режиме `code` для `execute_write` нужен новый UUID в `execution_id`. Повтор с тем же ID и тем же кодом возвращает журнал без повторной записи. Журнал можно прочитать через `runtime.get_execution(id)`. Если в ответе есть `result_ref` или `error_ref`, прочитайте данные частями через `runtime.get_result(ref, {offset, limit})` до `next_offset: null`.
- Один скрипт может успеть применить часть изменений. После конфликта или неизвестного результата проверьте журнал и состояние объекта перед новой записью. Уже отправленный запрос может завершиться после таймаута или закрытия клиента.

## Дополнительные настройки

| Переменная | Назначение |
|---|---|
| `INSALES_STORE_URL` | Публичный HTTPS-адрес магазина. |
| `INSALES_STORE_NAME` | Необязательное отображаемое имя. |
| `INSALES_API_KEY_ID` | Идентификатор API-ключа InSales. |
| `INSALES_API_KEY_PASSWORD` | Пароль API-ключа InSales. |
| `INSALES_MCP_DATA_DIR` | Необязательный каталог SQLite. По умолчанию `.data/` в репозитории. |
| `INSALES_MCP_UPLOAD_DIR` | Необязательный каталог изображений. По умолчанию `.uploads/` в репозитории. Настроенный каталог MCP никогда не очищает. |
| `INSALES_MCP_DOWNLOAD_DIR` | Необязательный каталог для `download_theme_asset`. По умолчанию `.downloads/` в репозитории. Настроенный каталог MCP никогда не очищает. |
| `INSALES_MCP_MAX_INLINE_BINARY_KB` | Максимальный бинарный файл в ответе `read_theme_asset_raw`, в килобайтах. По умолчанию 256. Больший файл скачивается отдельно. |
| `INSALES_MCP_WIDGET_SOURCE_ROOT` | Абсолютный корень локальных исходников виджетов для `source_files`. Без явной настройки чтение исходников из файлов запрещено. Пути в инструменте относительны этому корню. Символические ссылки запрещены. |
| `INSALES_MCP_AUTO_CLEANUP` | `1` по умолчанию. `0` отключает очистку при запуске и раз в час. Жёсткие ограничения SQLite остаются включены. |
| `INSALES_MCP_MAX_DATABASE_MB` | Максимальное число страниц SQLite в МиБ. По умолчанию 128. |
| `INSALES_MCP_MAX_WAL_MB` | Порог остановки записей при удерживаемом WAL. По умолчанию 32 МиБ. |
| `INSALES_MCP_MAX_RECORD_MB` | Максимальный размер JSON одной записи. По умолчанию 16 МиБ. |
| `INSALES_MCP_MAX_RECORDS` | Максимальное число сохранённых записей. По умолчанию 2000. Обновление существующей записи разрешено. |
| `INSALES_MCP_MAX_UPLOAD_MB` | Порог допуска изображений из стандартной `.uploads/`. По умолчанию 512 МиБ суммарно. |
| `INSALES_MCP_MAX_UPLOAD_FILES` | Порог допуска файлов из стандартной `.uploads/`. По умолчанию 2000. Обход ограничен четырёхкратным числом entries, включая директории. |
| `INSALES_MCP_API_ERROR_LOG` | `1` по умолчанию. `0` отключает локальный журнал ошибок запросов к InSales API. |

### Локальные данные и диагностика

Журнал операций в SQLite сохраняется между запусками. При включённой автоочистке сервер проверяет данные при старте и раз в час. Черновики без операций хранятся 24 часа, завершённые операции и их черновики — 7 дней. Крупные результаты чтения Code Mode хранятся сутки. После очистки результата Code Mode сохраняет ID запуска, чтобы предотвратить повторную запись. Операции с неизвестным результатом и незавершённые запуски сохраняются для проверки.

Стандартная `.uploads/` очищается от файлов старше 7 дней по времени изменения, если они не нужны сохранённым черновикам. Стандартная `.downloads/` очищается по тому же сроку вместе с основной базой `.data/`. Каталог в `INSALES_MCP_DOWNLOAD_DIR` обслуживает его владелец. При отдельной SQLite сервер сохраняет общую `.uploads/` целиком. Если стандартная папка превышает лимит, сервер отклоняет загрузку из неё. Каталог в `INSALES_MCP_UPLOAD_DIR` обслуживает его владелец и может задать его через символическую ссылку. Для стандартной `.uploads/` ссылка запрещена. Команда `npm run cleanup` показывает кандидатов на удаление и состояние хранилища, а `npm run cleanup -- --apply` запускает очистку.

Если старая база создана без поля `updated_at_ms`, для запуска укажите новый каталог через `INSALES_MCP_DATA_DIR`. Сохраните предыдущую базу, если в ней есть операции, которые ещё нужно проверить.

Журнал ошибок InSales находится в системном временном каталоге, в подкаталоге `insales-mcp-api-errors-<uid>`. В нём сохраняются метод, безопасный путь, статус и сведения о сетевом сбое. Реквизиты и тела запросов и ответов исключены. В строке запроса сохраняются разрешённые числовые параметры и `view=inventory`. Остальные значения заменяются на `[redacted]`. При `rate_limited` время ожидания указано в `retry_after_seconds`.

## Разработка

`npm run verify` проверяет сборку, стиль кода, контракт MCP, запуск через stdio и работу с тестовым транспортом. Для сверки встроенного REST-каталога с документацией запустите `python3 scripts/sync-public-api.py --check` с установленным `beautifulsoup4`. Та же команда без `--check` обновляет каталог.
