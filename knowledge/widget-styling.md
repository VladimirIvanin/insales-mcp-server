# Стили виджетов InSales 4-го поколения

`settings_form.json` виджета поколения 4 строго содержит две вкладки: `content` и `design`. Каждая вкладка — массив групп, каждая группа — объект с массивом `items` полей. Пустая форма: `{"content":[],"design":[]}`. Не размещай поля в корне или напрямую во вкладке; MCP отклоняет такую форму. У поля `name` — идентификатор, `label` — подпись; начальные значения задай в `settings_data.json`.

Для текста с HTML-разметкой (`<br>`, `<em>` и другие теги) выбирай `type="rich-text"`, чтобы форматирование редактировалось в интерфейсе. `type="text"` используй для текста без разметки. MCP предупреждает, если текстовое поле содержит HTML в `settings_data.json`.

`snippet.js` и стили подключаются для типа, а состояние, DOM и ресурсы принадлежат каждому экземпляру. Если целевая сборка common.v2.js предоставляет `WidgetLifecycle`, инициализируй экземпляры через `WidgetLifecycle.mount(widget, initialize)`. В старых сборках используй `$widget.each()` с ручной очисткой. Примеры доступны через `get_widget_standards(patterns=["runtime", "sliders"])`.

При создании блочного типа заполни `setup.json` стартовыми блоками. Базовые `fallback_id` изображений по назначению и соотношению сторон возвращает `get_widget_standards(scenario=create_widget)`; отдельно доступен `get_widget_standards(patterns=["fallback_images"])`.

Перед созданием или изменением `snippet.liquid` и `snippet.scss` учитывай системную обёртку и настройки `my-layout`:

- Платформа сама оборачивает `snippet.liquid` в `<div class="layout widget-type_{handle}"><div class="layout__content">…</div></div>`. В сниппете пиши только внутреннюю разметку: вторую `.layout__content` добавлять не нужно.
- Размещай стили секции в `snippet.scss` её типа; `my-layout` уже задаёт геометрию системной обёртки. Не переопределяй глобально `.layout` и `.layout__content` и не подключай общий CSS из шапки. Свои шрифты для всей темы подключай через настройки `custom-font-family-asset` и `custom-font-family-heading-asset`, которые читает `system_v4_fonts`; порядок действий и условия — `search_knowledge(query="system_v4_fonts")`. Общие CSS и Liquid-сниппеты создавай по задаче, которая требует изменения всей темы.
- Вертикальные и боковые отступы задавай настройками виджета. Для ссылок внутри виджета при необходимости явно укажи `text-decoration: none`, потому что `my-layout` подчёркивает ссылки по умолчанию.
- Старые `layout-pt`/`layout-pb` при стандартном мобильном коэффициенте `4` используй с `unit: "vw"`. Для `rem` или `px` нужен явный коэффициент `(0, 1]` на корне виджета: эти единицы не уменьшаются вместе с шириной экрана. Если нужны точные пиксельные отступы, создавай настройки `layout-pt-desktop-px`, `layout-pb-desktop-px`, `layout-pt-mobile-px`, `layout-pb-mobile-px` с `unit: "px"` и числовыми значениями по умолчанию (например, 112 и 64). Новые пиксельные значения не умножаются; мобильные имеют приоритет над десктопными, а при их отсутствии действует десктопное значение.
- Ссылки на категории и меню связывай с настройками виджета или `link_lists`, а не с фиксированными `/collection/...` и `collections.<handle>` в Liquid. Новым секциям давай понятный handle и собственное превью; ненужные размещения снимай с виджетлиста, а не прячь пустым Liquid и `display:none`.
- Типы настроек сверяй с `get_widget_standards`: `navigation` выбирает меню, `collection` выбирает категорию, `link` задаёт произвольную ссылку. Для формы покупки Common.js с `data-item-add` используй `data-product-id` на `<form>`, поля `variant_id` и `quantity`; подробности — `get_widget_standards(patterns=["product_forms"])`.
- `snippet.scss` компилируется внутри `.widget-type_{handle}`; `&` обозначает корень этого виджета. Не создавай эту обёртку заново в SCSS.
- Когда фон виджета задан настройкой `--bg`, начинай корневые стили с `@include background-color(--bg);`. Миксин задаёт фон и переключает палитру текста по `--bg-is-dark` / `--bg-is-light`. Для другого настроенного цвета секции можно вызвать миксин с его CSS-переменной.
- После этого миксина `var(--color-text)` уже контрастирует с `--bg`: на светлом фоне он тёмный, на тёмном — светлый. Для текста кнопки с фоном `--color-btn-bg` используй `var(--color-btn-color)`; `--color-btn-text` в `my-layout` отсутствует.
- Корневой шрифт и цвет помещай в `& { ... }`, а SCSS и Liquid форматируй по строкам. В `settings_form.json` каждому редактируемому полю дай `label`; числовому ползунку задай диапазон и при необходимости `with_btns`. Используй стандартные настройки дизайна виджета вместо собственных дублей.
- Основной и приглушённый текст бери из `var(--color-text)` и `var(--color-text-minor-shade)`; для поверхностей и кнопок используй подходящие переменные `--bg*` и `--color-btn-*`. Явные цвета допустимы для отдельных деталей дизайна, если они сохраняют читаемость на выбранном фоне.
- Для контента или фона на всю ширину используй настройки layout: `layout-wide-content`, `layout-wide-bg`, а для боковых отступов — `layout-edge` и `layout-side-padding`. Проверь, что нужные настройки определены у типа, а нужные значения заданы в настройках типа или экземпляра. Не компенсируй ограничение `.layout__content` растяжением внутреннего блока через `width: 100vw` и отрицательный `margin-left`.
- При переносе макета проверяй итоговые стили `.layout` и `.layout__content` в браузере: не дублируй их боковые и верхние отступы во внутренних элементах виджета.

Подробности по классам, переменным и структуре виджета найди через `search_knowledge` по `core-css-reference` и `widget-architecture/reference`, затем открой нужные разделы через `get_knowledge_section`.
