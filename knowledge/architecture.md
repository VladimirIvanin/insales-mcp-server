# Вызов операций через Code Mode

MCP публикует два инструмента: `execute_read({code})` и
`execute_write({execution_id, code})`. Все предметные имена в справочниках —
методы пространства `insales`, например `return await insales.list_stores({});`.
Код — тело async-функции. Найдите методы через `catalog.search({query})` и загрузите
их схемы через `catalog.describe({names})`. Без query поиск показывает области.
Повтор execution_id с прежним кодом возвращает
журнал без повторного исполнения; для проверки используйте runtime.get_execution(id).
Большие результаты доступны через runtime.get_result(ref,{offset,limit}) как части JSON.
При конфликте или неизвестном результате прекратите записи и проверьте состояние.

# Как устроена работа с InSales

## Слои API-клиента

Запросы не генерируются агентом на ходу. `HttpTransport` в `src/infrastructure/http/transport.ts` отвечает за Basic Auth, таймаут, лимиты, размер ответа, нормализацию ошибок и защиту URL/DNS. Режим `raw: 'bytes'` отдаёт байты и Content-Type, не декодируя ответ как UTF-8. Текст ассета остаётся строкой, бинарный файл до лимита возвращается в base64, а больший сохраняется на диск через `download_theme_asset`. Один stdio MCP-процесс получает один магазин и его credentials из environment при запуске; агент видит только безопасный `store_id`. `Api` держит credentials в памяти процесса и применяет backoff отдельно для магазина.

Поверх транспорта работает `InSalesClient` из `src/infrastructure/insales/admin-client.ts`. Он задаёт допустимые ресурсы и строит их маршруты и JSON-envelope: `pages`, `blogs`, `articles(blog_id)`, `products`, `variants(product_id)`, `themes`, `assets(theme_id)` и `widgetTypes(theme_id)`. MCP-операции используют этот клиент для обращений к магазину.

Эта схема похожа на `node-insales` по удобству ресурсных методов, но не наследует его старый сетевой слой: API-реквизиты не помещаются в URL, изменяемые request options не разделяются между параллельными вызовами, а произвольный host/path не принимается ресурсными методами.

## Контент и представление

Страница, статья и товар содержат данные. Тема определяет их вывод на витрине. Правка текста страницы меняет одну запись, правка общего Liquid-шаблона может изменить все использующие его страницы. Поэтому сначала определяй, где находится проблема: в данных, в Liquid или в JavaScript.

## Тема, тип и экземпляр виджета

Тип виджета задаёт Liquid, SCSS, JavaScript, форму настроек и значения по умолчанию. Экземпляр — размещённый блок с собственными настройками. Список виджетов задаёт область и порядок размещения.

Создание типа через `update_widget_type` не размещает его на странице. После записи возьми ID типа, найди существующий виджетлист через `get_page_structure` и `get_widget`, затем используй `create_widget`. Для размещения уже существующего экземпляра в дополнительном списке используй `create_widget`. Эти инструменты выполняют Theme Editor `widget.create` и `placement.add`; новые виджетлисты MCP не создаёт.

Размещённый виджет появится на странице, если её Liquid-шаблон выводит `widget_lists.<handle>.widgets`. Для секций темы используй типы и экземпляры виджетов; сниппет подходит для общей части разметки нескольких шаблонов или виджетов.

settings_data типа — значения по умолчанию. Его изменение не равно изменению настроек каждого существующего экземпляра. Для конкретного баннера сначала установи источник текста/цвета.

## Активная тема

is_published означает опубликованную тему. Правка её файлов может сразу повлиять на витрину. Пользователь выбирает нужную тему, агент получает ID и использует live_theme=true для такой задачи. Автоматической публикации нет.
