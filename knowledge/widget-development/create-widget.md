# Создать новый виджет

Для любого нового виджета, даже в уже существующей теме, все видимые тексты, подписи, ссылки и изображения сделай доступными через настройки или блоки, а товарные данные — через каталог. Понимай назначение каждой настройки, включая те, что использует `core.css` / `my-layout` или сама платформа. Если собираешь страницу, каждой самостоятельной секции дай отдельный экземпляр виджета; старые размещения снимай со списка, не скрывай их ограничением цикла в шаблоне. Для предмета поверх фона проверь альфа-канал файла и края на фоне секции: `.png` может содержать JPEG. Подробный справочник: `search_knowledge(query="editable-theme")`.

Перед передачей кода в MCP форматируй Liquid, JS, SCSS и JSON. Длинные исходники передавай через `source_files`, не минифицируй ради аргумента инструмента. Форматирование Liquid должно сохранять пробелы между строчными элементами и семантику `{%-` / `-%`.

Перед кодом запиши короткую спецификацию: результат → страница и секция → источник дизайна → источник контента → редактируемые поля → тип и библиотеки → проверки → открытые вопросы. Используй карту макета, если она есть. Если явно указаны блоки или библиотека, соблюдай это при создании; несоответствие выясни до записи.

При редизайне главной прочитай `get_page_structure` и проверь в layout вывод сквозных списков шапки и футера. Оцени их вместе с новым дизайном, даже если они не входят в контентный виджетлист страницы. Перед изменением шапки или футера спроси пользователя, согласен ли он на изменение всех страниц темы; до ответа не меняй эти сквозные области.

Перед выбором типа настройки прочитай `get_widget_standards` и схему подходящего существующего типа через `get_widget_type`. Для `linklists[widget_settings.*]` используй `navigation`, для `collections[widget_settings.*]` — `collection`; для произвольной ссылки подходит `link`. Если ссылка ведёт именно в выбираемую категорию, храни выбор категории и выводи её URL через `collections[widget_settings.*].url`.

Редакторский список карточек или слайдов делай `BlockListWidgetType` с подходящим шаблоном блоков из `list_block_templates` и `get_block_template`. Одиночные тексты, ссылки, файлы и параметры — настройки. Товары, цены и варианты считывай из каталога. Сам по себе цикл Liquid по товарам не требует блочного типа.

Отделяй промоизображения от фотографий товара. Просьба сгенерировать баннеры или промокарточки не означает согласие на сгенерированные фото товара. Если контент товара берётся с официального сайта, найди проверяемые официальные фото, сохрани ссылки на их источник в отчёте и только затем привязывай изображения к товару. Если фото недоступны, останови зависимую работу и спроси пользователя об источнике; не подменяй их генерацией.

У нового `BlockListWidgetType` с `block_template_handle` заполни `setup.json` стартовыми блоками. Если исходные изображения ещё не заданы, выбери `fallback_id` по назначению и соотношению сторон из приложенного руководства «Заглушки изображений для setup.json» и укажи ID в поле изображения блока. В MCP файл передаётся объектом в `parameters.setup`; локальный файл читает `read_widget_sources`. Поля блоков сверяй с выбранным шаблоном; для простого типа блоки в setup не нужны.

Сразу предусмотрите редактируемые текст, изображения и ссылки, а также стандартные настройки `my-layout`: фон, ширина фона и контента, верхний, нижний и боковые отступы. Для интерактивности прочитай правила `runtime` и подходящей библиотеки. После создания проверь виджет в редакторе и на витрине.

Для виджета карточки товара прочитай `product_forms` и проверь его на существующих товарах с разным наполнением. Если есть покупка из карточки, у каждой формы Common.js с `data-item-add` должны быть `data-product-id`, `variant_id` и `quantity`. Предупреждения валидатора исправляй до записи.
