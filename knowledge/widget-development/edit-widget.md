# Изменить существующий виджет

При изменении `settings_form.json` виджета поколения 4 сохраняй строгую структуру `{"content":[{"items":[{"name":"title","type":"text","label":"Заголовок"}]}],"design":[]}`. Поля находятся только внутри `items` групп; обе вкладки обязательны, даже если пусты. Начальные значения задавай в `settings_data.json`.

Если существующий текст в `settings_data.json` содержит HTML, используй для соответствующего поля `type="rich-text"`, чтобы редактор мог менять форматирование. Для обычного текста без разметки подходит `type="text"`.

Сначала прочитай конкретный экземпляр: `view=settings` для значений, `view=code` для кода, `view=full` для блоков. Определи, меняется настройка, список блоков, код или сама структура типа. Проверь другие экземпляры этого типа и сохрани их настройки и размещения.

Перед изменением кода составь короткую спецификацию: требуемое поведение, текущий источник данных, редактируемость, библиотеки и проверка. Для изменения только значений используй инструмент настроек; для редакторского списка — инструмент блоков. При сбое записи блоков перечитай `view=full` и сравни сохранённые поля. Не подменяй неверную ссылку поиском по названию.

Сохраняй текущую библиотеку и устройство слайдера. Исправление стрелок, свайпа или изоляции экземпляров само по себе не даёт основания переписывать его на TvistV1. Меняй библиотеку только по явной просьбе пользователя; если без миграции задачу выполнить нельзя, сначала объясни ограничение.

После замечания пользователя о повторяющемся паттерне проверь остальные виджеты текущей задачи с тем же устройством.

Если меняется виджет карточки товара, прочитай `product_forms` и проверь обновление на существующих товарах с разными вариантами, описанием и фото.
