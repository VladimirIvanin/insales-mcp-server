# Интерактивный слайдер

При изменении существующего слайдера сначала прочитай его Liquid, JS, CSS и `libraries`. Сохраняй текущую библиотеку и способ реализации, включая собственный JS. Не переписывай виджет на `tvist-v1` без явной просьбы пользователя о такой миграции. Если требуемое поведение невозможно реализовать в текущем устройстве, объясни ограничение и спроси о смене библиотеки до переписывания. Исправляй ошибки текущей реализации локально, включая смешивание экземпляров, отсутствие нужного свайпа и повторную инициализацию.

Для нового слайдера выбери подходящую доступную библиотеку по требованиям макета и теме; `tvist-v1` — один из вариантов. Проверь наличие выбранной библиотеки в `list_widget_libraries` и укажи её в `libraries` типа. Если используется собственный JS, проверь все требуемые действия, в том числе свайп. Редактируемые списки слайдов оформляй блоками; боковые одиночные баннеры могут быть файловыми настройками того же виджета.

Для каждого корня создай отдельный экземпляр слайдера и счётчик. Если целевая сборка предоставляет `WidgetLifecycle`, регистрируй уничтожение слайдера через `lifecycle.onCleanup` внутри `WidgetLifecycle.mount`. Для нуля слайдов пропусти инициализацию. Для одного отключи или скрой навигацию. Проверь два виджета одного типа с разным числом слайдов, стрелки, свайп и независимые счётчики.

В виджете на старой сборке перебирай корни через `$widget.each()` и очищай ресурсы каждого экземпляра вручную.

```js
$widget.each(function (_, element) {
  const $instance = $(element);
  const $slides = $instance.find('[data-slide]');
  if (!$slides.length) return;
  // Здесь используй текущую реализацию слайдера этого виджета.
  // Корень, состояние, счётчик и обработчики принадлежат только $instance.
  // При одном слайде скрой или отключи навигацию.
});
```

Это каркас, а не готовая инициализация. При событии редактора обновляй только связанный с `element` экземпляр; не подписывай каждый виджет на безусловное глобальное пересоздание. Если DOM слайдов изменился, используй методы обновления или уничтожения по правилам уже выбранной библиотеки.

Если для нового виджета выбран TvistV1 или пользователь явно запросил миграцию на него, его API и обработку событий смотри в `coder/splide-to-tvist/tvist-reference.md` и `patterns.md` через `search_knowledge`.
