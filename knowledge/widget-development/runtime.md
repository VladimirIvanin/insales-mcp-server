# Один тип, несколько экземпляров

`widgets_js` подключает `snippet.js` один раз для типа и задаёт `$widget` как коллекцию всех `.widget-type_{handle}`. `snippet.scss` также описывает тип. HTML, настройки и состояние принадлежат каждому экземпляру. Разные значения настроек передаются через разметку и локальные CSS-переменные.

Для интерактивного виджета объяви `commonjs_v2` в `info.json` и проверь наличие `WidgetLifecycle` в целевой сборке. `WidgetLifecycle.mount(widget, initialize)` вызывает `initialize(root, lifecycle)` для каждого найденного корня. Состояние и поиск элементов ограничивай этим корнем. Повторный mount сначала освобождает ресурсы прежнего экземпляра.

- Передавай `{ signal: lifecycle.signal }` в `addEventListener` и `EventBus.listen`. Подготовь состояние до подписки: шина может синхронно передать последние данные. Фильтруй события по источнику. Для настроек редактора сравнивай `data.widget_item_id` с `lifecycle.widgetItemId`. Если код читает уже применённую CSS-переменную, используй `lifecycle.onCssChange`.
- Через `lifecycle.onCleanup` освобождай таймеры, jQuery-обработчики и экземпляры библиотек. Редактор автоматически очищает экземпляры в своих обёртках при удалении или замене разметки. Если разметку меняет собственный скрипт витрины, сначала вызови `lifecycle.destroy()` для одного экземпляра или `unmount()`, возвращённый `mount`, для всей группы.
- В старой сборке используй `$widget.each()` и сохраняй функцию очистки отдельно для каждого корня. Вызывай её перед повторной инициализацией или удалением. Для `EventBus.subscribe` сохрани ссылку на обработчик и передай её в `EventBus.unsubscribe`.

Проверь повторный mount, удаление и два экземпляра с разными данными. Контракт и примеры найдёшь через `search_knowledge(query="WidgetLifecycle", topic="widget-architecture")`.
