# Контент, оформление, иконки и изображения

Для поколения 4 форма настроек строго имеет вид `{"content":[{"items":[{"name":"title","type":"text","label":"Заголовок"}]}],"design":[]}`: две вкладки, в каждой массив групп, в группе массив `items`. Пустая форма — `{"content":[],"design":[]}`. Начальные значения полей храни в `settings_data.json`.

Редактируемый контент хранится в настройках виджета, блоках или объектах магазина. У новых виджетов определяй стандартные `my-layout` настройки: `bg`, `layout-wide-bg`, `layout-wide-content`, `layout-pt`, `layout-pb`, `layout-edge` и боковые отступы там, где они нужны. Связывай значения со стилями через переменные конкретного экземпляра. Не встраивай оформление секции в глобальный CSS.

При стандартном мобильном коэффициенте `4` старые `layout-pt/pb` используй с `unit: "vw"`: величина `vw` уменьшается вместе с экраном, а коэффициент её компенсирует. Значения в `rem` или `px` умножаются на `4` без уменьшения самой единицы; для них нужен явный коэффициент `(0, 1]` на корне виджета. Если дизайн требует точных пиксельных отступов, используй `layout-pt-desktop-px`, `layout-pb-desktop-px`, `layout-pt-mobile-px`, `layout-pb-mobile-px`. Например, для `layout-pt-desktop-px` и `layout-pt-mobile-px` укажи `unit: "px"` в форме и числа `112` и `64` в данных. Эти значения не проходят через мобильный коэффициент; без мобильного значения наследуется десктопное.

У каждой настройки должно быть понятное назначение в Liquid, JS, SCSS, `core.css` / `my-layout` или механизмах платформы. Не объявляй поле только для вида, но и не считай его лишним по отсутствию обращения через `widget_settings`. Ссылка на главную, внутренний якорь, `cart_url` и `search_url` могут оставаться техническими маршрутами. При ошибке «Изображение должно находиться внутри каталога загрузок» перемести локальный файл в `INSALES_MCP_UPLOAD_DIR` или стандартную `.uploads` и повтори загрузку: отказ происходит до API. Имя `.png` не гарантирует прозрачность — проверь содержимое файла и композицию на витрине.

Типы полей бери из `get_widget_standards`. Меню выбирается полем `navigation`, категория — `collection`, произвольная ссылка — `link`. Значение категории — handle, поэтому URL выводи через `collections[widget_settings.<имя>].url`, а не как значение поля. Сверяй `settings_form.json`, `settings_data.json` и Liquid вместе.

Если текст настройки содержит HTML-разметку (например, `<br>` или `<em>`), выбирай `type="rich-text"`: редактор должен позволять менять форматирование. `type="text"` оставляй для текста без разметки; при несовпадении MCP предупреждает.

Проверяй имя `insales-icons` по справочнику и по макету. Для изображений уточняй, нужен ли AccountFile блока или файловая настройка, загружай файл подходящим инструментом и проверяй URL на витрине. Если шаблон блока не позволяет редактировать символ или изображение, выясни желаемое решение до хардкода по названию карточки.

Для товара с контентом из официального источника используй проверяемые официальные фото и фиксируй URL их происхождения. Генерацию по запросу применяй к промоматериалам; если официальных фото товара нет, сначала уточни у пользователя допустимый источник.
