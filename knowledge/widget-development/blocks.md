# Редактируемые блоки

Для повторяемого редакторского контента используй `BlockListWidgetType` и шаблон с нужными полями. Сверяй `block_template_handle` и поля выбранного шаблона через `list_block_templates` и `get_block_template`, а структуру полей и их параметры — по детальному ответу `get_block_template` до создания. Слайды, плитки, FAQ и редакторские отзывы требуют добавления, удаления и изменения порядка в редакторе. Динамическая выдача товаров из коллекции может оставаться простым виджетом.

Для нового блочного типа заполни `setup.json` стартовыми блоками по полям выбранного шаблона. Если изображения пока нет, используй `fallback_id` из приложенного руководства «Заглушки изображений для setup.json»: выбери назначение и близкое соотношение сторон. Эти ID предназначены для setup нового типа; они не являются ID AccountFile конкретного магазина.

Связь категории или товара хранится в соответствующем поле блока, изображение — в поле файла. Название блока не служит ключом для поиска объекта. Для своего изображения AccountFile сначала загрузи файл и передай полученный ID в поле блока. При изменении существующих блоков через `replace_widget_blocks` используй ID файлов магазина, а не fallback_id из setup. После `replace_widget_blocks` прочитай `get_widget` и сравни все ссылки, порядок и файлы. При `execution_unknown` не создавай обходной Liquid-код: выясни расхождение на сохранённых данных.
