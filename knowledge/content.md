# Контент: страницы, статьи, товары

## Выбор объекта

Для страницы, статьи и товара используй `read_content` с `kind=page|article|product` и `mode=list|get`. Для статьи сначала получи блоги (`kind=blog`, `mode=list`), затем передай конкретный `blog_id`. MCP дополнительно проверяет принадлежность статьи блогу.

Для полного чтения существующей карточки используй `read_product_card`: он возвращает данные публичного Product API и `revision`. Для точечного изменения текста и SEO есть `update_product`; остальные публичные поля карточки меняет `update_product_card` с `base_revision` из полного чтения. Параметры товара меняй через `update_product_properties`: он сохраняет неуказанные значения, а удаляет только явно перечисленные названия. Новую опцию варианта добавляй через `add_product_option`: она получает начальное значение на всех существующих вариантах. Вариант или изображение читай через `read_product_item`, затем меняй через `change_product_variant` или `change_product_image`.

Для категорий товаров витрины используй `read_content(kind=collection)`: `parent_id` и `position` описывают дерево. Отдельный API `categories` относится к категориям склада и не подключён к MCP. `read_content(kind=collect)` показывает прямые связи товара с категориями. `change_collection` создаёт/меняет категорию или удаляет только пустую конечную категорию; `change_collection_membership` добавляет или снимает товар в обычной категории. Смарт-категории читаются, но их фильтры и ручной состав не редактируются.

## Поддерживаемые поля

| Объект | Поля |
|---|---|
| Страница | title, content, permalink, html_title, meta_description, meta_keywords |
| Статья | title, content, notice, permalink, author, published_at, html_title, meta_description, meta_keywords |
| Товар | title, description, short_description, html_title, meta_description, meta_keywords |

HTML в content/description/notice сохраняй при текстовых правках; не добавляй исполняемый код для обычного редактирования текста.

## Изменение и создание

Прочитай объект и передай revision как base_revision в операцию записи. MCP проверяет версию перед запросом и сверяет результат. При конфликте перечитай объект и учти изменения. Хеш не даёт атомарной блокировки между чтением и записью.

Для создания страницы не передавай id и base_revision; обязательны title и content. Для статьи также обязательны author, published_at и blog_id. Создание реально записывает контент и может сделать его доступным на витрине; это не неопубликованный CMS-черновик. Размещение страницы в меню инструмент не выполняет.

### Создание товара

Используй `create_product` с `product.title` и минимум одним элементом `variants`. Допускаются цены, артикулы, штрихкоды, остатки, размеры, опции, свойства, поля, SEO, видео, комплект, категории, аналогичные и сопутствующие товары в пределах публичных Product API. Если вариантов несколько, у каждого должен быть одинаковый набор названий опций, а комбинации значений должны различаться.

Опции товара задают измерения вариантов. Первый вариант создаётся вместе с товаром через `product.options`, последующие варианты — через `variants[].options`. При создании или изменении варианта передавай значения **всех** текущих опций товара, даже если меняешь одно значение. Комбинация должна быть уникальной для товара. Публичный ответ варианта содержит `option_values`, а названия опций — в `product.option_names`; MCP сопоставляет их по `option_name_id`. Добавление измерения к существующему товару выполняй через `add_product_option` с обязательным `default_value`, затем при необходимости меняй полный набор опций каждого варианта.

Публичный Product API заменяет весь набор параметров при записи `properties_attributes`: передача одного параметра удаляет остальные. Для точечного изменения используй `update_product_properties` с `set: [{"title":"Память","value":"12 ГБ"}]`; для удаления — `remove_titles: ["Память"]`. Чтобы задать несколько значений одного параметра, передай несколько элементов `set` с тем же названием и разными значениями. Инструмент читает текущий набор, записывает полный итоговый набор и проверяет результат отдельным чтением. Не передавай `properties_attributes` через обычное изменение карточки.

Изображения передай в `images` с уникальными `key`. Для каждого изображения укажи ровно один источник: публичный `src` с HTTPS либо `local_path` относительно `.uploads/` в репозитории. Абсолютный путь внутри разрешённого каталога тоже допустим; `INSALES_MCP_UPLOAD_DIR` может выбрать другой каталог. Локальный файл должен быть JPEG, PNG, GIF или WebP до 20 МБ. Изображения варианта укажи через `variants[].image_keys`; сервер загрузит изображения товара, получит их ID и привяжет к вариантам. `image_ids` другого товара использовать нельзя. Для одного изображения существующего товара используй `change_product_image`, для 1–30 независимых изображений — `create_product_images` с элементами `{product_id, fields:{src|local_path, title?, filename?}}`. После вызова проверь `get_operation`: он вернёт статус и ID каждого элемента. Повтор того же пакета не отправляет POST повторно; для элементов со статусом `failed` подготовь новый пакет после просмотра ошибки. Для `execution_unknown` сначала выясни результат записи, не создавай новую операцию вслепую. Затем передай полученный ID в `change_product_variant(fields.image_ids)`.

Пример аргументов `create_product`:

```json
{
  "store_id": "configured-store-id",
  "product": { "title": "Телефон", "description": "Описание", "is_hidden": false },
  "variants": [
    { "sku": "PHONE-BLACK", "price": 10000, "options": [{ "title": "Цвет", "value": "Чёрный" }], "image_keys": ["front"] },
    { "sku": "PHONE-WHITE", "price": 11000, "options": [{ "title": "Цвет", "value": "Белый" }], "image_keys": ["back"] }
  ],
  "images": [
    { "key": "front", "src": "https://cdn.example.com/front.jpg" },
    { "key": "back", "local_path": "back.jpg" }
  ],
  "collection_ids": [123]
}
```

Для категории витрины сначала найди её ID через `read_content(kind=collection)`, затем передай в `collection_ids`. Указанные `similar_ids` и `supplementary_ids` связываются после создания. `category_id` — категория складского каталога, другой ресурс.

Создание выполняется последовательно: сначала скрытая карточка с первым вариантом, затем дополнительные поля, изображения, варианты и связи; в конце карточка становится видимой, если `product.is_hidden` не задан или равен `false`. Если шаг завершился ошибкой, `get_operation` покажет ID созданных объектов и причину; не повторяй новый `create_product` вслепую. Неопределённый результат записи сервер автоматически не отправляет повторно.

## Runtime-проверка записи

Сценарии создания и изменения товаров, вариантов, опций и изображений проверяются автоматическими тестами с имитацией публичного API.
